## Design decisions

- D1 Redirect list lives in `src/lib/redirects.ts` (`export const OLD_URL_REDIRECTS: { source: string; destination: string }[]`), imported by `next.config.ts` and mapped to `{ ...r, permanent: true }`. One list feeds both config and the check script. Full table: `.agents/tasks/old-url-redirects.md`. If `destination: "/#contact"` fails config validation, use `"/"` and note it.
- D2 `/insights/lims-urs-template` is canonical (it has the article depth and BlogPosting). The download moves into the post via a new optional `download` field on `Post`, rendered by `src/app/insights/[slug]/page.tsx` and emitted as a `DigitalDocument` node; the route `src/app/resources/lims-urs-template/` is deleted and 301'd. Deleting the route is required because Next redirects run before the filesystem anyway, and a dead page file would be confusing.
- D3 Doorway: add `noindex?: true` to `Landing`. Kharar, Ambala, Shimla get it (no real local client/content known). Zirakpur stays indexed: max 3% overlap, it borders Panchkula and is part of the Tricity, so the page's "nearby, in-person possible" angle is truthful. Routes stay (reversible: delete the flag). `areaServed` drops Ambala and Shimla (they were agent-added with a CONFIRM note, never owner-confirmed); Kharar stays (Mohali district, Tricity periphery).
- D4 Panchkula: rewrite `about`, `answer`, one section and FAQs of `/mobile-app-development-panchkula` and `/web-development-company-panchkula` around the HQ angle using only public, checkable facts (Panchkula sectors and Industrial Area Phase I/II, Mansa Devi, proximity to Chandigarh/Zirakpur/Pinjore/Kalka, types of local businesses) and how meetings/Academy work from the Panchkula base. No office address, client, or number claims.
- D5 Sitemap: drop `priority` and `changeFrequency` everywhere (Google ignores both; uniform values are noise). `lastModified` for non-post pages comes from fixed ISO constants in `src/content/page-dates.ts` (never `new Date()`), seeded from `git log -1 --format=%cs` of the source files: everything 2026-10-04 except `/process` 2026-09-28 and `/academy` 2026-09-29; bump a path's constant only when its content really changes (pages edited in this task get the implementation date).
- D6 Authors: `Author` gains `credentials?: string[]` (e.g. GxP/validation experience lines) and `PILLAR_AUTHORS: Partial<Record<Pillar, string>>` (e.g. `regulated: "<id>"`) in `src/content/authors.ts`. New `getPostAuthor(post)` = `getAuthor(post.author ?? PILLAR_AUTHORS[post.pillar])`. All empty → behaviour identical to today.
- D7 Contact: Contact always POSTs to `/api/contact` when an endpoint is configured; whether one is configured is decided at build time on the server (`Home.tsx` passes `formEndpoint: boolean` to the client `Contact`). Server forwards to `CONTACT_FORM_ENDPOINT` (server-only, new) or else `NEXT_PUBLIC_LEAD_FORM_ENDPOINT`; https only. No endpoint → today's mailto flow unchanged, plus a WhatsApp link in the sent state. Unauthenticated endpoint protected only by honeypot + in-memory per-IP rate limit (per server instance) — flag in docs and final report.
- D8 Work: mark `clinic` and `ops-agent` as `sample: true` in `WORK`; `WorkCard` shows a visible "Sample build, not client work" label; `/work` H1/description stop claiming every item was put live. PVgenix and LIMS keep their copy (repo marks only the two as placeholders).
- D9 External links: plain `<a href="…" rel="noopener">` in the same tab (no nofollow, no `_blank`), via a small `Source` helper in `src/components/insights/Prose.tsx`. Official sources only (verified list below).
