## 0. Ground rules for every item

- Commands: `npm run lint`, `npm run build`. Serve prod with `npx next start -p 3100` as a background process (3000 is often busy). Crawl with
  `node .kiro/skills/seo-audit/scripts/audit.mjs http://localhost:3100 --out .agents/seo-audit-2026-10-04.md` (exit 1 = errors). Stop the server when done.
- Next 16 has breaking changes. Before touching metadata, sitemap, robots, OG images, routing, ISR or scripts read the guide in `node_modules/next/dist/docs/01-app/`:
  `01-getting-started/14-metadata-and-og-images.md`, `02-guides/incremental-static-regeneration.md`, `02-guides/caching-without-cache-components.md` (route segment `revalidate` must be a literal number), `03-api-reference/03-file-conventions/02-route-segment-config/dynamicParams.md`, `03-api-reference/03-file-conventions/01-metadata/{sitemap,robots}.md`, `03-api-reference/04-functions/generate-metadata.md` (`verification`), `02-guides/scripts.md` + `03-api-reference/02-components/script.md`. The project does NOT enable `cacheComponents`, so `revalidate` / `dynamicParams` segment configs are valid.
- HARD RULES: never invent reviews, ratings, testimonials, client names/logos, case-study numbers, prices/fees, addresses, timings, author names, placement stats, survey data. Costs/salaries in articles = "indicative" ranges + "get a written quote" language (copy the tone of `src/content/insights/app-development-cost-india.tsx`). No competitor claims, no "Top 10" lists, no unverifiable superlatives. No backdating; keep existing `published` dates; set `updated` only on posts whose content you really edit (use 2026-10-04 or the real `Get-Date` day of the edit). Don't change existing URLs/slugs (if unavoidable: 301 in `next.config.ts`).
- Owner-data features render NOTHING when their data/env is empty. No placeholder text visible on the site.
- Never tick a checklist item from code reading alone. Items marked "needs verification during implementation" must be checked on the built + served site (rendered HTML, crawler, Lighthouse).
- No new npm dependencies (GA4 via `next/script`, not `@next/third-parties`). Lighthouse only via `npx --yes lighthouse ...` (npx cache, not global); if it cannot run (no Chrome/network), record that as "not verified" instead of guessing.

## Design decisions (recorded once, used by all phases)

D1. Scheduled publishing (Next 16, no cacheComponents).

- New file `src/content/insights/schedule.ts`: `todayIST()` returns `YYYY-MM-DD` in `Asia/Kolkata` via `Intl.DateTimeFormat("en-CA",{timeZone:"Asia/Kolkata"})`; honours a server-only override `CONTENT_NOW` (YYYY-MM-DD, local QA only, documented "never set in production"). `isPublished(post, today = todayIST())` = `post.published <= today`.
- `src/content/insights/index.ts`: keep `POSTS` (all, sorted) as the private registry; export functions that evaluate at call time (never module-level constants, because ISR re-renders in a long-lived process): `getPublishedPosts()`, `getPost(slug)` (returns only published posts; add `getAnyPost` only if needed internally), `relatedPosts(post)` (published only, same pillar first), `postsByPillar()`, `isPostSlugPublished(slug)`.
